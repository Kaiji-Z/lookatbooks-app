## ⭐ 推荐用法:Web UI(双击 exe 即可)

**普通用户(不懂会计/Python/MCP 的小企业主)首选**:

1. 拿到 `lookatbooks-setup.exe`(Inno Setup 安装版)或绿色版 `lookatbooks.exe`
2. 双击桌面快捷方式「lookatBooks 记账」
3. 浏览器自动打开 → 走 5 步月度向导

**Web UI 是全功能入口**:建账、上传单据、AI 识别、人审、登账、期末结转、出报表、激活付费 — 全在浏览器里完成,无需命令行或 AI agent。

导航栏（从左到右）：**月度记账**（主页面）→ **凭证**（凭证中心）→ 资产 → 报表 → 账簿 → 辅助核算 → 设置 → 帮助。

- **月度记账**：4 步向导（上传 → AI 识别+审核 → 体检+登账+结转 → 报表+报税），日常记账主入口
- **凭证**：凭证中心，全局管理所有凭证（手动新增/审核/撤回/删除/红字冲销），与月度向导共用数据

5 步月度向导:
- ① 上传单据(拖拽,批量):银行流水 / 数电票 XML/OFD/PDF/PNG / 工资表 / 现金日记账
- ② AI 识别 + 审核:规则预填(零 AI)+ 交叉匹配(零 AI)+ LLM 兜底,你逐张点 ✓ 确认
- ③ 体检:10 项自动检查(借贷平衡/科目合规/库存现金为负等),✕ 会挡住登账
- ④ 登账 + 期末结转:人审二次确认后锁定账面
- ⑤ 出报表:资产负债表 / 利润表 / 现金流量表 + 报税文件导出(付费)

### 为什么推荐 Web UI 而不是 CLI/MCP?

- **Web UI 设计目标**:让不懂会计、不懂 Python 的小企业主独立完成一整月账
- **CLI/MCP 是进阶选项**:适合批量脚本、AI agent 自动化、debug 场景
- **数据安全**:Web UI 是单机本地服务(127.0.0.1),数据不出本机硬盘

### 进阶:CLI / MCP 选项(可选)

- **CLI**(`lookatbooks <command>`):24 个命令,与 Web UI 等价,适合脚本批处理
- **MCP**(配 Claude Code / OpenCode / ZCode 等 agent):42 个结构化 tools,适合让 AI 自动化记账

详见 [README.md](../../README.md) 的 CLI 与 MCP 章节。

## 它是给谁用的

**小规模纳税人小企业 / 自媒体 / 小工作室**——没有专职会计,每月/季度要记账+报税,但不想啃会计知识。

典型画像:
- 月流水几万到几十万
- 收入主要来自:客户转账、平台打款
- 支出主要:供应商货款、办公、工资、少量费用
- 手上的原始单据:**银行流水 Excel**(网银导出)、**数电票**(XML/OFD/PDF/图片,电子税务局下载或商家开具)、**工资表 Excel**
- 每季度要去**电子税务局**申报增值税,每年要报企业所得税

**你不碰会计知识**,lookatBooks 帮你把"单据 → 凭证 → 报表 → 报税文件"全跑了,你只负责**丢文件 + 看结果确认 + 最后去税局点提交**。

## 二、核心概念速览（非会计也能懂）

### 记账流程的"五步"

```
import   →   bookkeep   →   approve   →   post    →   close   →   report/filing
丢单据       翻译成凭证      你审核确认      登账        期末结转     出报表/报税
(待办)       (生成草稿)     (草稿→已审核)   (不可逆)    (不可逆)
```

| 步骤 | 干什么 | 谁干 | 可逆? |
|------|--------|------|-------|
| `import` | 把单据文件（流水/发票/工资表）读进系统 | 工具（确定性解析） | 可（重导会去重） |
| `bookkeep` | 把单据**翻译成会计凭证**（借XX/贷XX） | 规则引擎（高频）+ agent 的 LLM（长尾） | 可（只产生草稿） |
| `approve` | 你点头说"这张凭证对" | 你 | 可 |
| `post` | 正式记进账本 | 你确认后工具执行 | **不可逆**（错了红字冲销） |
| `close` | 月末把收入费用结转到"本年利润" | 工具（确定性） | **不可逆** |
| `report`/`filing` | 出三大报表 + 报税文件 | 工具（确定性） | 只读 |

### bookkeep 是什么（最常被问）

`bookkeep` = **"把单据翻译成记账凭证"**。这是整个工具最核心、最省你时间的环节。

它做三件事：
1. 拿出所有待办单据
2. 对每一笔判断该记成什么凭证——**两层**：
   - **规则引擎**（不调 LLM，又快又准）：销售收款/付供应商/工资/手续费/数电票 → 直接判定
   - **agent 的 LLM**（处理长尾）：规则没认出来的奇怪交易，agent 用它自带的 LLM 判断
3. 生成**凭证草稿**（带置信度 + "AI 为什么这么记"的推理说明），等你确认

**关键**：bookkeep 只产生草稿，不登账。你随时可以改、删、重跑，没风险。

## 三、三种入口，选你顺手的

| 入口 | 适合谁 | 怎么用 |
|---|---|---|
| **对 agent 说话**（MCP） | 大多数人，最省事 | ZCode 里说人话，agent 通过记账向导自动引导 |
| **CLI 命令** | 喜欢控制感、要写脚本 | 终端敲 `lookatbooks ...` |
| **Web 看板** | 想直观看凭证/报表 | `lookatbooks ui`，浏览器看（只读） |

三者调的是**同一套核心**，账套是同一个 `.easybook` 文件。

### ⭐ 推荐用法：对 agent 说"帮我记账"（傻瓜式）

lookatBooks 有一个**记账向导**(`bookkeeping_wizard_tool`)，agent 一调就知道当前该干嘛、该问你什么。你**不需要背任何命令、不需要懂会计**：

1. 在 ZCode 里（任意目录，建议 cd 到你的财务目录如 `D:\公司A财务\`）
2. 对 agent 说：**"帮我记账"**（或"这个月账记一下"）
3. agent 调向导，向导检测状态后告诉 agent 该问你什么
4. 你只需回答 agent 的问题（公司名？税号？文件在哪？这张凭证对吗？）
5. agent 一步步带你走到出报表、报税文件

向导会根据账套状态自动判断在 7 个阶段的哪一步：未建账→待导入→待记账→待审核→待登账→待结转→已完成。中途断了，重新说"继续记账"也能从断点接上。

## 四、一次完整记账报税的全流程（以 2026-06 为例）

### 用法 A：直接对 agent 说人话（推荐）

打开 ZCode（已配好 lookatbooks MCP），在项目目录里直接说：

> **第 1 句（首次建账，只做一次）：**
> "帮我建个账套 `my.easybook`，公司叫'某某工作室'，纳税人识别号 91110000XXXXXXXXXX，小规模纳税人，起始期间 2026-06。"

agent 调 `init_ledger_tool`，几秒建好。

> **第 2 句（每月/季记账）：**
> "把 2026-06 的账记一下。银行流水在 `bank_2026-06.xlsx`，进项发票在 `invoice-in.xml`（我的税号是 91110000XXXXXXXXXX），工资表在 `payroll-2026-06.xlsx`。"

agent 自动做：
1. `import` 三个文件
2. `bookkeep` 用规则引擎处理高频交易（销售/采购/工资等），生成凭证草稿
3. 对规则没命中的长尾交易，**agent 用自带 LLM 判断**（查科目表 → 判断 → `create_voucher` 落地）
4. 把所有凭证展示给你看（含"AI 为什么这么记"的推理）

然后它会**停下来问你**：
> "我生成了 8 张凭证，其中 2 张置信度较低（XXX 交易），你看一下对不对？确认无误后我帮你登账。"

你看一眼，说"对"或"第3张科目应该是XX"。确认后 agent 登账、期末结转。

> **第 3 句（出报表/报税）：**
> "出一下 2026-06 的资产负债表，再生成报税文件。这个季度销售额大概 18 万。"

agent 生成：资产负债表/利润表/现金流量表的 **Excel 模板**（可直接导入电子税务局）+ 增值税/所得税**填表数据** + 一份**逐项填表指引**。

**最后一步（你亲自做，工具不碰）：**
你登录电子税务局 → 财务报表报送 →【导入】那个 Excel → 申报表按指引手工填 → 提交。这步**必须你本人做**（实名认证+扫脸），工具不替你申报——这是法律要求。

### 用法 B：自己敲 CLI 命令

```bash
# 1. 建账(一次性)
lookatbooks init my.easybook --company-name "某某工作室" \
    --tax-id 91110000XXXXXXXXXX --taxpayer-type small_scale --start-period 2026-06

# 2. 导入这个月的单据
lookatbooks import my.easybook bank_2026-06.xlsx --period 2026-06
lookatbooks import my.easybook invoice-in.xml --period 2026-06 --tax-id 91110000XXXXXXXXXX
lookatbooks import my.easybook invoice-in.ofd --period 2026-06 --tax-id 91110000XXXXXXXXXX  # OFD 格式(纯stdlib解析)
lookatbooks import my.easybook invoice-in.pdf --period 2026-06 --tax-id 91110000XXXXXXXXXX  # PDF 格式(内置)
lookatbooks import my.easybook payroll-2026-06.xlsx --period 2026-06

# 3. AI 记账(规则引擎处理高频交易, 生成凭证草稿)
lookatbooks bookkeep my.easybook --period 2026-06

# 4. 看凭证对不对
lookatbooks list-vouchers my.easybook --period 2026-06

# 5. 审核 + 登账 + 期末结转
lookatbooks approve my.easybook --period 2026-06 --all
lookatbooks post my.easybook --period 2026-06        # ⚠️ 登账不可逆
lookatbooks close my.easybook --period 2026-06       # ⚠️ 结转不可逆

# 6. 出报表 / 报税文件
lookatbooks report my.easybook balance-sheet --period 2026-06
lookatbooks filing my.easybook --period 2026-06 --quarterly-sales 180000 --output-dir ./output

# 7. (可选) 启动 Web 看板
lookatbooks ui my.easybook   # 浏览器打开 127.0.0.1:8000
```

> **注意**：CLI 模式下长尾交易的处理走 MCP（让 agent 用 LLM）。纯 CLI 不接 LLM，规则没命中的会留 pending，需要手工或切换 agent 处理。

第 6 步生成的文件在 `./output/`：
- `资产负债表_2026-06.xlsx` / `利润表_2026-06.xlsx` / `现金流量表_2026-06.xlsx` → **税局可导入**
- `申报指引_2026-06.md` → 按它填增值税/所得税申报表

## 五、数据从哪来（你要准备什么）

| 单据 | 哪里拿 | 格式 |
|---|---|---|
| **银行流水** | 企业网银 → 明细查询 → 导出 | Excel（工行/招行/建行已内置识别；其他银行首次会问一下列含义） |
| **数电票（发票）** | 电子税务局 → 税务数字账户 → 全量发票查询 → 下载 **XML** | XML（带税局签名，法定格式；**别下 PDF**） |
| **工资表** | 自己用 Excel 做的工资单 | Excel（列：姓名/应发工资/社保/公积金/个税） |

**为什么数电票要 XML 而不是 PDF？** XML 是结构化数据（金额/税额/税号都是字段），工具直接读，零错误；PDF 只是给人看的预览，要 OCR 才能读，会出错。这是 2024 年后数电票全国推广带来的最大便利。

## 六、LLM 判断的分工（重要架构）

这是 lookatBooks 区别于"传统记账软件"和"纯 LLM 记账"的关键设计：

| 交易类型 | 谁处理 | 为什么 |
|---|---|---|
| **高频交易**（销售收款/付供应商/工资/手续费/数电票进销项） | **规则引擎**（不调 LLM） | 又快又准又免费，确定性 |
| **长尾交易**（规则没命中的奇怪交易） | **agent 自带的 LLM** | 不重复付费、不另配 key、agent 能解释推理 |

工具做机器擅长的（数字、校验、状态机），agent 做 LLM 擅长的（理解、判断）。**你不需要为工具单独配 LLM API key**——agent 自己就是个 LLM。

## 七、安全边界（你必须知道的红线）

我把丑话说前面，避免你踩坑：

1. **登账（post）和结转（close）不可逆**。错了只能红字冲销（生成反向凭证），不能直接改。所以工具强制：登账前 agent 会把凭证一张张展示给你确认。**你确认前它不会登账**（server 端有硬校验：有未审核凭证时 post 直接拒绝）。
2. **工具不替你申报**。它生成"可导入的财务报表"+"填表指引"，但**去电子税务局点提交必须你本人**（实名+扫脸）。这是《代理记账管理办法》的硬要求，也是保护你——申报责任在你，不在 AI。
3. **税务优惠判断要你确认**。比如"季度≤30万免税""小型微利5%所得税"，工具按政策算，但最终适用与否涉及你的具体情况，agent 会把计算依据给你看，你来定。
4. **金额全程不会算错**。工具用 Decimal（不是浮点），借贷强制平衡，最坏情况是科目分错（可改），不会出现"金额算错"或"借贷不平"。

### 三层防御（对抗 AI 不可靠）

| 层 | 机制 | 例子 |
|---|---|---|
| **文档层** | SKILL.md + AGENTS.md | `lookatbooks-shared` 写明不可逆矩阵 + 人审三步协议 |
| **协议层** | tool description 写明前置/不可逆/人审 | `post_period_tool` 标注"前置:必须approve / 不可逆:HIGH" |
| **机器层** | server 硬校验 | post 时若有草稿未审核 → **拒绝并返回 needs_approval** |

## 八、报税落地（这是法律姿态）

`filing` 生成两类文件，你拿去电子税务局操作：

| 文件 | 你怎么用 |
|------|----------|
| **资产负债表/利润表/现金流量表 Excel 模板** | 电子税务局 → 我要办税 → 财务报表报送 → 【导入】→ 选这个 Excel → 一键填表（**用的是税局官方导入功能，合法**） |
| **申报指引 markdown** | 按指引在增值税/所得税申报表里手工录入（税局主要靠系统预填+手工勾稽） |

**工具不碰的事**（红线）：
- ❌ 不模拟登录电子税务局
- ❌ 不自动提交申报
- ❌ 不保存任何账号密码

### 税务计算要点（小规模纳税人）

- **增值税**：季度销售额≤30万免税（普票部分）；3%减按1%（2027-12-31前）；**专票必税**（即使季度≤30万）。
- **附加税费**：增值税×12%（城建7%+教育3%+地方教育2%）×50%（六税两费减半）。
- **企业所得税**：小型微利（应纳税所得额≤300万+从业≤300+资产≤5000万）按 5%；否则 25%。
- **个税**：累计预扣法，7 档 3%-45%。

政策变动频繁，`tax_config.yaml` 带有效期，过期政策自动失效。具体以税局校验为准。

```json
{
  "mcpServers": {
    "lookatbooks": {
      "command": "C:\\Users\\kaiji\\AppData\\Roaming\\Python\\Python314\\Scripts\\lookatbooks-mcp.exe",
      "args": []
    }
  }
}
```

> 路径要指向你全局 Python 的 Scripts 目录下的 `lookatbooks-mcp.exe`。配置后**重新进入项目会话**让 ZCode 加载。
